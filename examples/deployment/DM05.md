# DM0.5 / MEM deployment

Run an OpenDM joint-space checkpoint through PhyAI's native model, processor,
Engine and RPC service. The Tianji client uses the existing robot adapter,
StopAndRefill scheduler and controller lifecycle. No shared framework modules
are changed.

## Prepare the checkpoint

Use a complete OpenDM export containing `config.json`, model safetensors
(including the index for sharded weights), and the Gemma3 processor/tokenizer
files. An optimizer or FSDP training-state file alone is not an inference export.
Keep the SFT dataset's `norm_stats.json` alongside the checkpoint.

The server configuration must reproduce the training camera order, image labels,
robot name, control mode, speed string, state order, delta mask and normalization
statistics. The supplied example uses:

```text
state / action: [left_joint_1..7, left_gripper, right_joint_1..7, right_gripper]
units:          joint radians, grippers normalized to [0, 1]
camera order:   head_left, left_wrist, right_wrist
delta mask:     joint dimensions true, gripper dimensions false
```

Baseline and TAL-trained full-weight exports use the same inference path. TAL is
a training loss; there is no TAL switch or alignment step during inference.

## Inspect and start the model server

Use a working PhyAI CUDA environment with the deployment dependencies installed
(`uv sync --group deployment`). Run from the checkout root. These print-only
commands do not initialize a model, connect to ROS, or call controller services:

```bash
uv run --group deployment python -m examples.deployment.serve_dm05 --print-config
python -m examples.deployment.tianji \
  --config examples/deployment/configs/tianji_dm05.yaml --print-config
```

Start the model-only service in the inference environment:

```bash
uv run --group deployment python -m examples.deployment.serve_dm05 \
  policy.checkpoint=/path/to/dm05-export \
  processor.norm_stats=/path/to/norm_stats.json \
  'task=Put the green block on the blue block'
```

`configs/dm05_tianji.yaml` contains the defaults. A private YAML can override any
subset with `--config /path/to/server.yaml`. Paths inside YAML resolve against
the checkout root; absolute paths remain absolute. The default endpoint is
`tcp://127.0.0.1:5555`. The server never imports ROS or enables robot controllers.

## Connect the existing Tianji client

Install the client in the robot's native ROS 2 environment as described in
[Robot / inference environment isolation](ROBOT_ENVIRONMENTS.md). Inspect the
merged configuration before executing it. Unlike the print-only command above,
the following command **takes control of the robot and can move it**:

```bash
python -m examples.deployment.tianji \
  --config examples/deployment/configs/tianji_dm05.yaml
```

This merges the DM0.5 timing overrides over the existing Tianji YAML. It uses
50 source actions/s, executes the first 20 actions of each chunk, and retains
the existing 200 Hz interpolated actuator loop. Set `schedule.action_hz` to
`dataset_fps / action_stride` for other datasets. The prompt's `speed` string
does not configure control frequency or a controller velocity ratio.

The existing Tianji adapter maps gripper feedback from
`robot.gripper_limits_rad` (default `[0.0, 1.6]`) to `[0, 1]`, and clamps command
values to that normalized range. Confirm that the training data uses that same
calibration and open/closed convention. This example does not infer calibration
from model weights.

For separate hosts, set the server's `endpoint` to the desired listening
interface and the client's `remote.endpoint` to that host. Use the existing RPC
lifecycle and robot stop behavior; no alternative controller loop is introduced.

## Images and MEM history

Official OpenDM evaluation pads RGB images to a centered black square, resizes
with OpenCV bilinear interpolation to 448x448, then applies the checkpoint's
Gemma3 image processor. The DM0.5 processor follows that order.

The robot client already square-pads images for transport. Set
`processor.wire_image_size` to the native longest image side so that transport
only adds padding. The supplied value 960 matches recordings at 960x540; the
Tianji client defaults to `robot.camera_size=[540,960]`. Check this against the
actual recording geometry. If the client resizes pixels before transport, its
PIL interpolation can differ from the official OpenCV preprocessing. A different
crop, stretch or camera order changes the model input.

`DM05History` retains head-camera images received with prediction requests. It
samples up to 32 earlier 1-second slots, with a 0.25-second timestamp tolerance,
and excludes the current frame. Valid history is ordered oldest to newest;
missing slots use official `<unused1>` padding. Each valid frame is encoded to
16 visual tokens. Cached images are reduced to 448x448 and retained for the
configured history duration; starting a run clears history and resets the seed.

This cache uses request receipt times, not sensor capture timestamps. The RPC
contract has no continuous image stream, so frames between prediction requests
are unavailable. Slow inference or StopAndRefill pauses can leave history slots
empty. The processor accepts explicitly supplied historical frames for offline
comparison, but the live example does not reconstruct unobserved frames.

## Official input/output comparison

Reference: [dexmal/opendm at a6016e4](https://github.com/dexmal/opendm/tree/a6016e48a4ebcb21bb8496cd9ce830d28f6f51cf),
particularly `opendm/data/transforms.py` and `opendm/model/dm05/dm05_arch.py`.

| Stage | Official OpenDM | This integration |
|---|---|---|
| Current observations | RGB cameras, state, task and metadata | Same fields, adapted from the existing RPC arrays |
| State normalization | Quantiles, clipping, epsilon 1e-6, zero-stat handling | Existing normalizer wrapped with matching clipping/zero handling |
| Text | Robot/control/speed/task, camera labels, 256-bin state tokens | Same template and tokenizer |
| History | 16 tokens per valid frame, padded missing slots | Same model inputs for supplied history; request-only live cache as described above |
| Prefix | SigLIP, Gemma3 projector/text stack, image-block mask and RoPE | Native PhyAI layers, SDPA, runner-owned per-request K/V |
| Action generation | AdaRMS expert, noise at t=1, 10 Euler steps to t=0 | Same schedule and BF16 policy, with FP32 action projections |
| Normalized output | `(1, 50, 32)` for the released checkpoint | Same shape; padded dimensions are not masked by default, matching official inference |
| Physical output | Slice valid dimensions, inverse normalization, joint deltas anchored to current state | Same operations in the processor; RPC returns finite float64 `(50, 16)` absolute targets |

`DM05Entry` loads weights with the existing strict loader. Only the unused
language-logit head and unused final affine expert norm are skipped. The
normalized model output is FP32; converting decoded actions to float64 for RPC
does not add numerical precision.

## Offline validation

Validation used the released `DM05-MEM` weights, synthetic RGB observations and
16-D states, identical initial noise, and 10 Euler steps. Both no-valid-history
and two-valid-history cases retained the remaining padding slots. OpenDM ran
from its unmodified commit in its Transformers 5.3 environment; PhyAI used
Transformers 5.8.1 for tokenization. Both used Torch 2.11, CUDA 12.8, BF16 and SDPA
on one H800. Repository dependency pins were not changed.

All model-ready input tensors were bit-identical: IDs, attention mask, token
types, current pixels, history mask and history pixels. The strict loader loaded
1471 tensors with zero missing or unexpected tensors. Comparisons below use
only the 16 valid action dimensions, not the padded dimensions:

| Valid history frames | Single-step velocity cosine (32-D) | Final action cosine (16-D) | Normalized MAE (16-D) | Maximum absolute error (16-D) |
|---|---|---|---|---|
| 0 | 0.9999958 | 0.9999701 | 0.0011704 | 0.0091799 |
| 2 | 0.9999955 | 0.9999695 | 0.0013117 | 0.0193459 |

The native output repeated bit-identically for fixed inputs/noise. The complete
`DM05Policy -> EnginePolicy -> Engine` path also returned the expected `(50,16)`
float64 physical targets; synthetic-stat decoded action cosines were 0.9999879
and 0.9999819. History reset, quantile clipping, zero-stat handling, delta
decoding, image padding, configuration validation and lazy service import were
checked separately. Model test artifacts stay in ignored `.cache/` as required
by this repository.

These checks establish input equivalence and close numerical agreement, not
bit-identical network outputs or task success. Shared fused kernels and BF16
rounding differ from the reference. This change has not been tested on live
Marvin hardware or benchmarked on Thor.

## Current limits

- Batch size one, joint-space actions, and a prefix shorter than the Gemma3
  sliding window (4096 tokens for the released weights).
- No language/CoT generation, RTC, CUDA graph capture or acceleration claim.
- No native OpenDM WebSocket API: deployment uses PhyAI's existing RPC protocol.
- Inference loads a complete weight export; training and checkpoint conversion
  remain in OpenDM.
